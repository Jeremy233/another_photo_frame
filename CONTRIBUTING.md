## 中文

感谢你愿意参与 AnotherPhotoFrame。项目还在规范阶段，接口和目录结构随时可能调整；动手做较大的改动前，请先开 Issue 讨论。

### 接受什么

- ✅ **代码**：功能、修复、测试、文档。
- ✅ **预设**：纯数据的布局预设（尺寸、边距、图层位置、占位 slot、输出参数）。预设格式见规范 §8；schema 冻结之前，预设相关的贡献请先开 Issue。
- ❌ **素材**：V1 **不接受任何素材贡献**（规范 D-20），包括但不限于：
  - 相机或镜头品牌的 Logo、线稿、贴图；
  - 字体文件；
  - 照片、样张、水印图片、签名；
  - 任何第三方拥有版权或商标的图形。

仓库只放代码与预设。提交的预设里也不能嵌入素材，只能用占位 slot 引用，由用户在本地导入自己的素材。用户素材的版权由用户自行负责。

> 测试需要的样图必须是程序生成的合成图（参见 `docs/illustrations/source/`），放在专门的 `fixtures/` 目录里，并在 PR 里说明生成方式。

### 开发环境

- macOS 26 或更高版本，Apple Silicon
- Xcode 26（Swift 6.2 或更高）

### 测试要求

- 每个模块是 `Packages/` 下一个独立的 Swift Package。改动了哪个 Package，就在那个 Package 里运行：

  ```bash
  cd Packages/<PackageName>
  swift test
  ```

  如果仓库在 iCloud 同步目录下，加上 `--scratch-path "$TMPDIR/<PackageName>-build"`（原因见 [README](README.md#构建与测试)）。
- 新功能和修复都要带测试；修 bug 时先写一个能复现问题的测试。
- 涉及规范里的公式或验收用例（如 AC-03）时，在测试名或注释里注明对应的规范章节。
- CI 会对 `Packages/` 下的每个 Package 运行 `swift test`，全部通过才能合并。新增 Package 不需要改 CI 配置。

### 提交要求

- 一个 PR 只做一件事，保持改动小而完整。
- 提交信息用英文祈使句，首行不超过约 72 个字符，例如 `Add panorama slice warnings`。需要解释原因时在正文里写。
- 不要提交构建产物、个人照片、导出结果或任何密钥（`.gitignore` 已经排除了常见情况）。
- 修改行为规则时，同步更新规范或对应 Package 的 README，并在 PR 里说明。
- 提交的代码以 [Apache License 2.0](LICENSE) 授权。按照许可证第 5 条，你提交的贡献默认按该许可证授权给项目。

### 报告问题

- Bug 和功能建议：使用 GitHub Issues，附上系统版本、复现步骤和预期结果。请不要上传你不想公开的照片。
- 安全问题：不要公开提交 Issue，请按 [SECURITY.md](SECURITY.md) 私下报告。

## English

Thanks for your interest in AnotherPhotoFrame. The project is still in the specification stage and its APIs and layout may change at any time; please open an issue to discuss larger changes first.

### What we accept

- ✅ **Code**: features, fixes, tests, documentation.
- ✅ **Presets**: data-only layout presets (sizes, margins, layer positions, placeholder slots, output settings). The preset format is described in spec §8; until the schema is frozen, please open an issue before contributing presets.
- ❌ **Assets**: V1 **accepts no asset contributions of any kind** (spec D-20), including but not limited to:
  - camera or lens brand logos, line art or badges;
  - font files;
  - photos, samples, watermark images or signatures;
  - any graphics whose copyright or trademark belongs to a third party.

The repository holds only code and presets. Presets must not embed assets either; they reference placeholder slots that users fill with their own locally imported assets. Users are responsible for the rights to their own assets.

> Images needed by tests must be synthetic and generated by code (see `docs/illustrations/source/`), kept in a dedicated `fixtures/` folder, with the generation method described in the PR.

### Development environment

- macOS 26 or later, Apple Silicon
- Xcode 26 (Swift 6.2 or later)

### Testing

- Each module is a standalone Swift Package under `Packages/`. Run the tests in every package you changed:

  ```bash
  cd Packages/<PackageName>
  swift test
  ```

  If the repository is in an iCloud-synced folder, add `--scratch-path "$TMPDIR/<PackageName>-build"` (see the [README](README.md#build-and-test) for why).
- New features and fixes need tests; for a bug fix, start with a test that reproduces it.
- When a test covers a formula or acceptance case from the spec (such as AC-03), name the spec section in the test name or a comment.
- CI runs `swift test` for every package under `Packages/`, and all of them must pass before merging. New packages are picked up without changing the CI configuration.

### Commits and pull requests

- One pull request, one change; keep it small and complete.
- Write commit messages in English, imperative mood, with a first line of about 72 characters or less, e.g. `Add panorama slice warnings`. Explain the why in the body when needed.
- Do not commit build products, personal photos, exports or any secrets (`.gitignore` covers the common cases).
- When you change a behavior rule, update the spec or the package README as well and say so in the PR.
- Code is licensed under the [Apache License 2.0](LICENSE). Under section 5 of the license, contributions you submit are licensed to the project under those terms.

### Reporting issues

- Bugs and feature requests: use GitHub Issues with your macOS version, steps to reproduce and the expected result. Please don't upload photos you don't want to be public.
- Security issues: do not open a public issue; report them privately as described in [SECURITY.md](SECURITY.md).
